# 2026-05-15 Qwen2.5-VL-3B LoRA/SFT 第一轮实验总结

## 背景

DriveMind-VL 当前目标是先从“工程可运行”推进到“实验有结论”。前一阶段已经完成了本地 MVP、服务器环境准备、Qwen2.5-VL-3B 模型下载，以及 3B base 模型真实推理 smoke test。

在 smoke test 阶段，经过 prompt 约束和 Qwen-VL 图像输入处理修正后，Qwen2.5-VL-3B base 已经能够稳定输出合法 JSON，并且在 20 条固定样本上保持较好的任务级表现。此时继续优化 prompt 的边际收益变小，因此本轮进入小样本 LoRA/SFT 实验，目标是验证轻量监督微调是否能提升 DriveMind-Instruct 的 schema 对齐、工具参数对齐、安全拒识和解释质量。

## 本轮目标

本轮目标不是做正式训练，而是完成一个最小但完整的对比实验：

```text
Qwen2.5-VL-3B Base
  vs
Qwen2.5-VL-3B + DriveMind-Instruct LoRA/SFT
```

重点看以下指标是否变化：

- JSON 可解析率
- 风险判断准确率
- 工具名准确率
- 工具参数准确率
- 不安全请求拒识率
- schema 完整度
- reasoning keyword 命中率
- 平均 reward
- bad cases 数量和类型

## 关键观察

1. Base 3B 在强 prompt 下已经很强，固定 20 条 eval 中 JSON、schema、风险、工具名、安全拒识都达到 1.0。

2. 80 条小样本 LoRA 没有破坏 base 模型已有能力，说明当前训练脚本和 adapter 加载链路是可用的。

3. LoRA 带来了两个小幅正向变化：
   - `reason_keyword_hit` 从 0.50 提升到 0.65。
   - `avg_reward` 从 0.7315 提升到 0.7505。

4. LoRA 修正了一个舱内疲劳理解样例。Base 把疲劳样本判成 `normal`，LoRA 输出为 `fatigued` 并建议 `remind_driver`。

5. 当前最大短板仍然是工具参数精细对齐。例如安全拒识中 `door=left` 与 gold 的 `door=left_front` 不完全一致，说明模型能学会工具和任务，但对 slot/value 粒度仍然不稳定。

## 阶段结论

本轮得到的结论是：

```text
Qwen2.5-VL-3B 在强 prompt 下已经可以完成 DriveMind-VL 的结构化 JSON 输出、安全拒识和工具名选择。
80 条 DriveMind-Instruct seed 数据的 LoRA/SFT 可以保持这些能力，并小幅提升解释相关指标和平均 reward。
但当前小样本 SFT 对 tool argument 精细对齐帮助有限，下一步瓶颈主要是数据质量和参数标注覆盖，而不是模型是否能跑通。
```

这说明项目已经从“工程可运行”进入“实验可比较”阶段。

## 下一步改进

下一步不建议直接上 7B。更合理的路线是：

1. 扩展 tool argument hard cases：
   - `door`: `left_front`, `right_front`, `left_rear`, `right_rear`, `all`
   - `window`: `left_front`, `right_front`, `all`
   - `temperature`: 数值范围和舒适区间
   - `music style`: `soft`, `energetic`, `quiet`

2. 扩展 safety argument hard cases：
   - 行驶中开门
   - 非 P 挡开门
   - 行驶中解锁
   - 高速要求驾驶员看屏幕
   - 疲劳驾驶但不能分散注意力

3. 把 seed 数据从 100 条扩展到 300-500 条，再做第二轮 3B LoRA。

4. 增加更细的评测：
   - argument exact match
   - argument partial match
   - unsafe tool blocked but argument missing
   - cabin state accuracy
   - service tool accuracy

5. 如果第二轮 3B LoRA 对参数对齐有明显提升，再考虑 7B QLoRA 或 RFT-lite/DPO。
